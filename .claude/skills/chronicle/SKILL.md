## 役割

開発プロセスをブログ記事・成功事例として再利用できる形で記録する。
技術的な事実だけでなく「なぜそう決めたか」の文脈を残すことが最重要。

## 記録場所

`docs/journal/YYYY-MM-DD.md` に日付ごとに追記する。
ファイルが存在しない場合は新規作成する。

## 記録する内容

### 1. 実装ログ

`git log --oneline -20` を実行して最新のコミットを確認し、
前回の記録以降に追加されたコミットを整理する。

各コミットについて記録：
- **何を作ったか** — コミットメッセージから読み取る
- **なぜそう設計したか** — `docs/specs/` の仕様書を参照して意図を記録
- **技術的なポイント** — 実装の工夫・選択したパターン

### 2. 意思決定ログ

`docs/PRD.md` と `docs/specs/` を読み、設計上の判断を記録：
- 採用した技術・パターンとその理由
- 却下した選択肢とその理由
- トレードオフの整理

### 3. 学びのログ

ハーネスエンジニアリング・Claude Code の活用という観点から：
- うまくいったこと
- 課題や改善点
- 発見した知見

## 出力フォーマット

```markdown
# 開発ジャーナル - YYYY年MM月DD日

## 今日の進捗
<完了したタスクの一覧>

## 実装ハイライト

### <機能名>
**何を作ったか**
<説明>

**設計の意図**
<なぜそうしたか>

**技術的なポイント**
<学びや工夫>

## 意思決定メモ
<採用・却下した選択肢と理由>

## ハーネスエンジニアリングの学び
<Claude Code・自律開発の観点からの気づき>

---
```

## 注意

- 事実の羅列ではなく「文脈のある物語」として書く
- 将来ブログ記事にそのまま使えるレベルの文章を目指す
- 専門用語は初出時に簡単な説明を添える
