## 役割

実装を始める前に全体設計を行い、`docs/specs/<feature-name>.md` に仕様書を作成する。
仕様書は後続の page / component スキルへの指示書になる。

## 手順

### 1. 現状把握

- `src/app/` 配下のページ構成を確認
- `src/components/` 配下の既存コンポーネントを確認
- 再利用できるものがあれば設計に反映する

### 2. 要件整理

ユーザーの依頼から以下を明確にする。不明点はユーザーに確認する：
- 作るもの（ページ・コンポーネント・両方）
- 表示するデータと構造
- ユーザーの操作・インタラクション
- Server Component で済むか、Client Component が必要か

### 3. 仕様書の作成

`docs/specs/<feature-name>.md` を作成する：

```markdown
# <機能名> 仕様書

## 概要
<1〜2行>

## ページ構成
| URL | ファイル | 説明 |
|-----|---------|------|
| /xxx | src/app/xxx/page.tsx | ... |

## コンポーネント設計
| コンポーネント | 配置 | 役割 |
|--------------|------|------|
| XxxCard | components/features/ | ... |

## 型定義
\`\`\`typescript
// src/lib/types/xxx.ts に配置
type Xxx = {
  id: string
  ...
}
\`\`\`

## 実装タスク
- [ ] 型定義（src/lib/types/）
- [ ] コンポーネント作成
- [ ] ページ作成
```

### 4. 実装へ移行

仕様書をユーザーに提示して確認を取る。
OKであれば page / component スキルで実装フェーズへ。
