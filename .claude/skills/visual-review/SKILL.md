## 役割

Playwright MCP を使ってアプリの主要ページのスクリーンショットを撮影し、
デザインの崩れ・UIの問題点・改善提案をレポートする。

---

## STEP 1: 開発サーバーの起動確認

Bash で開発サーバーが起動しているか確認する：

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000
```

- `200` が返れば起動済み → STEP 2 へ
- それ以外なら Bash でバックグラウンド起動する：

```bash
npm run dev &
sleep 5
```

---

## STEP 2: スクリーンショット撮影

Playwright MCP の `browser_navigate` と `browser_take_screenshot` を使い、
以下のページを順番にキャプチャする。

| ページ | URL |
|--------|-----|
| ホーム | http://localhost:3000 |
| レッスン一覧 | http://localhost:3000/lessons |
| レッスン詳細（記事タブ） | http://localhost:3000/lessons/what-is-prompt |
| レッスン詳細（ハンズオンタブ） | ハンズオンタブをクリックして撮影 |
| ダッシュボード | http://localhost:3000/dashboard |

各ページで：
1. `browser_navigate` でページを開く
2. ページの読み込みが完了するまで待機
3. `browser_take_screenshot` でキャプチャ

---

## STEP 3: デザインレビュー

撮影した各スクリーンショットを順番に見て、以下の観点でレビューする：

### チェック項目

**レイアウト**
- [ ] コンテンツが画面からはみ出していないか
- [ ] 余白（padding/margin）が均等か
- [ ] カードや要素が揃って並んでいるか

**タイポグラフィ**
- [ ] 見出し・本文・キャプションの階層が明確か
- [ ] Markdown の見出し・段落・コードブロックが正しくスタイルされているか
- [ ] フォントサイズが読みやすいか

**カラー・コントラスト**
- [ ] テキストと背景のコントラストが十分か
- [ ] アクセントカラー（青・緑・紫）が統一されているか

**レスポンシブ（1280px 基準）**
- [ ] ナビゲーションが崩れていないか

**コンポーネント固有**
- [ ] タブの切り替えが視覚的にわかりやすいか
- [ ] バッジ・ボタン・カードが正しく表示されているか
- [ ] プログレスバーが表示されているか

---

## STEP 4: レポート出力

以下の形式でレポートを出力する：

```
## ビジュアルレビュー結果

### ✅ 問題なし
- （問題のない項目）

### ⚠️ 改善推奨
- （小さな問題や改善提案）

### 🔴 要修正
- （明らかな崩れや重大な問題）

### 修正優先順位
1. 最優先：...
2. 次に：...
```

問題が見つかった場合は、具体的なコンポーネント名とファイルパスを示す。
