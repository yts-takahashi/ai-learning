---
name: ship
description: PRDを読んで未完了の機能をすべて自律的に実装し完成させる最上位オーケストレータースキル。「完成させて」「全部作って」「shipして」「eラーニングツールを仕上げて」など、プロダクト全体の完成を求める依頼があれば必ずこのスキルを使う。ユーザーの介入なしに最後まで完走する。
---

## 役割

`docs/PRD.md` を読み、未完了のタスクをすべて `develop` スキルのフローで実装し、
プロダクトを完成状態まで自律的に進める。

## 実行フロー

```
1. PRD読み込み     — 全タスクと完成定義を把握
2. 状態確認        — 何が完了済みか・何が残っているか
3. タスク実行ループ — 未完了タスクを順番に実装
4. PRD更新         — 完了したタスクにチェックを入れる
5. 完了報告        — 全タスク完了を報告
```

---

## STEP 1: PRD 読み込み

`docs/PRD.md` を読み、以下を把握する：
- 実装タスク一覧（フェーズ1〜3）
- 各フェーズの依存関係（フェーズ1が終わってからフェーズ2）
- 完成の定義

---

## STEP 2: 現状確認

以下を確認して、すでに完了しているタスクを特定する：
- `src/` 配下のファイル構成
- `content/` 配下のコンテンツファイル
- PRDのチェックボックスの状態（`[x]` が完了済み）

---

## STEP 3: タスク実行ループ

未完了タスクをPRDの順番通りに1つずつ実行する。
**前のタスクが完了してから次に進む**（フェーズ間の依存があるため）。

各タスクの実行手順：

### 3-1. タスクの解釈
PRDのタスク名から「何を作るべきか」を具体化する。
`docs/specs/` に既存の仕様書があれば参照する。

### 3-2. develop スキルのフローで実装
以下を順番に実行する：

**設計**
- `docs/specs/<task-name>.md` に仕様書を作成する
- 既存コードとの整合性を確認する

**実装**
- 型定義 → コンポーネント → ページの順で作成する
- コンポーネント配置ルール：
  - 汎用部品 → `src/components/ui/`
  - ナビゲーション等 → `src/components/layout/`
  - 機能固有 → `src/components/features/`
- Server Components をデフォルトとし `"use client"` は最小限にする
- `any` 型は使わない

**検証**
```bash
npm run lint
npx tsc --noEmit
```
エラーがあれば修正してから次へ進む。

**コミット**
Conventional Commits 形式で日本語コミット：
```
feat(<scope>): <実装内容>
```

### 3-3. PRD更新
タスク完了後、`docs/PRD.md` の該当チェックボックスを `[x]` に更新する：
```
- [x] 完了したタスク名
```

---

## STEP 4: 完了報告

全タスク完了後、以下を報告する：
- 完了したタスクの一覧
- 作成されたファイルの一覧
- 動作確認方法（`npm run dev` で確認できる旨）

---

## STEP 5: VISUAL REVIEW（デザインレビュー）

完了報告の後、`visual-review` スキル（`.claude/skills/visual-review/SKILL.md`）を実行する。

```
.claude/skills/visual-review/SKILL.md を読み、デザインレビューを実行してください。
```

---

## STEP 6: IMPROVE（改善アイデア生成・実装）

VISUAL REVIEW の後、`improve` スキル（`.claude/skills/improve/SKILL.md`）を実行する。
PRD の全タスクが完了している場合は必ずこのステップを実行する。

```
.claude/skills/improve/SKILL.md を読み、プロダクト改善を実行してください。
PRD の全実装タスクはすでに完了しています。
改善アイデアを生成し、優先度の高い上位3件を実装してください。
```

---

## STEP 7: CHRONICLE（開発記録）

すべてのステップ完了後、必ず `chronicle` スキル（`.claude/skills/chronicle/SKILL.md`）を実行する。
このステップは省略しない。

```
.claude/skills/chronicle/SKILL.md を読み、開発記録を作成してください。
直前の ship セッションで実装・改善した内容を docs/journal/ に記録してください。
git log --oneline -20 で今回のセッションのコミットを確認して記録してください。
```

---

## 判断基準（迷ったとき）

| 状況 | 判断 |
|------|------|
| Server か Client か | Server を選ぶ |
| コンポーネントの配置 | `features/` に置く |
| タスクの解釈が曖昧 | PRDの「完成の定義」を優先する |
| 依存ライブラリが必要 | `npm install` して進める |
| フェーズ2以降のタスクがフェーズ1に依存 | フェーズ1をすべて完了してから進む |

---

## 中断・再開について

途中で中断した場合は、再度「shipして」と依頼すれば：
- PRDのチェックボックスで完了済みタスクを確認
- 未完了のタスクから再開する
