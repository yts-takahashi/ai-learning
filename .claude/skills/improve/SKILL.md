---
name: improve
description: 開発タスクがなくなったときに改善点・アイデアを自律的に生成し実装するスキル。「改善して」「アイデアを出して」「improve して」「良くして」など、プロダクト改善・アイデア出しの依頼や、ship・launch の全タスク完了後に自動呼び出される。PRD・コード・UIを分析して優先度付きの改善リストを生成し、上位のものを自律的に実装する。
---

## 役割

PRD・コード・UI・コンテンツを多角的に分析し、改善アイデアを生成・優先順位付けして、
上位の改善を自律的に実装する。開発タスクがゼロになったときのエンジンとして機能する。

---

## 実行フロー

```
1. SCAN     — プロジェクト現状の全体把握
2. ANALYZE  — 改善領域の特定と分析
3. IDEATE   — 改善アイデアの生成（最低10件）
4. PRIORITIZE — 優先度付け（Impact × Effort マトリクス）
5. IMPLEMENT  — 上位3件を自律実装
6. REPORT   — 実施結果と残アイデアの報告
```

---

## STEP 1: SCAN（現状把握）

以下をすべて確認する：

### コード・構成
- `src/app/` — ページ構成とルーティング
- `src/components/` — 既存コンポーネント一覧
- `docs/PRD.md` — PRDと完成定義
- `docs/specs/` — 機能仕様書
- `docs/journal/` — 開発ジャーナル（存在すれば）

### コンテンツ
- `content/lessons/` — レッスンファイルの数・構成
- 各レッスンのフロントマター（タイトル・章・難易度・所要時間）

### 品質
```bash
npm run lint
npx tsc --noEmit
```

---

## STEP 2: ANALYZE（改善領域の特定）

以下の8領域を必ず評価する：

| 領域 | 評価観点 |
|------|---------|
| **UX/UI** | ナビゲーション・視認性・レスポンシブ対応・ダークモード |
| **パフォーマンス** | 画像最適化・コード分割・キャッシュ戦略 |
| **アクセシビリティ** | aria属性・キーボード操作・コントラスト比 |
| **コンテンツ品質** | レッスンの深さ・ハンズオンの充実度・クイズの質 |
| **学習体験** | 進捗可視化・達成感・学習パス |
| **新機能** | PRDに未記載だが価値の高い機能 |
| **コード品質** | 重複排除・型安全性・テスタビリティ |
| **SEO・メタデータ** | OGタグ・structured data・サイトマップ |

---

## STEP 3: IDEATE（アイデア生成）

各領域から改善アイデアを具体的に生成する（最低10件）。

アイデアの記述形式：
```
## アイデア: <タイトル>
- **領域**: <UX/UI | パフォーマンス | アクセシビリティ | コンテンツ品質 | 学習体験 | 新機能 | コード品質 | SEO>
- **説明**: <何を・なぜ・どう改善するか>
- **Impact**: High / Medium / Low（ユーザー価値）
- **Effort**: High / Medium / Low（実装コスト）
- **実装概要**: <具体的な変更内容>
```

アイデア例（参考、実際のコード分析に基づいて生成すること）：
- 検索機能（レッスン全文検索）
- ブックマーク機能
- 学習時間トラッキング
- レッスン完了時の達成バッジ
- チャプター間の関連レッスン表示
- モバイルのスワイプナビゲーション
- コードブロックのシンタックスハイライト強化
- フォントサイズ調整機能
- キーボードショートカット（j/k でレッスン移動）
- プリントCSS（レッスンを印刷できる）

---

## STEP 4: PRIORITIZE（優先度付け）

Impact × Effort マトリクスで分類する：

```
              Low Effort    Medium Effort   High Effort
High Impact   [即実装]      [計画的に実装]   [要検討]
Med Impact    [次点]        [余裕あれば]    [保留]
Low Impact    [いつか]      [スキップ]      [スキップ]
```

**即実装対象（High Impact × Low Effort）** を上位3件選定する。
選定できない場合は **High Impact × Medium Effort** から選ぶ。

---

## STEP 5: IMPLEMENT（実装）

選定した上位3件を順番に実装する。

各アイデアの実装手順：

### 5-1. 設計確認
- 既存コードへの影響範囲を確認
- 変更するファイルを特定
- 破壊的変更がないか確認

### 5-2. 実装
- 型定義 → コンポーネント → ページの順
- Server Components をデフォルト、`"use client"` は最小限
- `any` 型は使わない

### 5-3. 検証
```bash
npm run lint
npx tsc --noEmit
```
エラーがあれば修正してから次へ。

### 5-4. コミット（各アイデアごとに）
Conventional Commits 形式：
```
improve(<scope>): <改善内容の要約>
```
例：
- `improve(ui): コードブロックにシンタックスハイライトを追加`
- `improve(ux): チャプター完了時の達成バッジを実装`
- `improve(a11y): キーボードナビゲーションを改善`

---

## STEP 6: REPORT（報告）

実施結果と未実施アイデアを報告する：

```markdown
## 改善実施レポート

### 実施した改善（3件）
1. **<タイトル>** — <変更内容の簡潔な説明>
2. **<タイトル>** — <変更内容の簡潔な説明>
3. **<タイトル>** — <変更内容の簡潔な説明>

### 残りの改善アイデア（優先度順）
| 優先度 | タイトル | 領域 | Impact | Effort |
|--------|---------|------|--------|--------|
| 1      | ...     | ...  | High   | Medium |
| 2      | ...     | ...  | High   | High   |
...

### 次回「improve して」と依頼するとリストの続きから実装します
```

---

## 判断基準（迷ったとき）

| 状況 | 判断 |
|------|------|
| 破壊的変更が必要なアイデア | スキップして次のアイデアへ |
| 外部ライブラリが必要 | `npm install` して進める |
| バックエンドが必要なアイデア | `develop` スキルに委譲して次のアイデアへ |
| PRDに反するアイデア | スキップ |
| コンテンツ改善のアイデア | `content` スキルに委譲 |

---

## 再実行について

「improve して」と再度依頼すると：
- 前回の「残りの改善アイデア」リストがあれば続きから実装
- なければ再度 SCAN → IDEATE から実行
