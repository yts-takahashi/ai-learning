---
name: improve
description: 開発タスクがなくなったときに改善点・アイデアを自律的に生成し実装するスキル。「改善して」「アイデアを出して」「improve して」「良くして」など、プロダクト改善・アイデア出しの依頼や、ship・launch の全タスク完了後に自動呼び出される。PRD・コード・UIを分析して優先度付きの改善リストを生成し、バックログに保存してすべて実装しきるまで自律継続する。
---

## 役割

PRD・コード・UI・コンテンツを多角的に分析し、改善アイデアを生成・優先順位付けして、
**バックログに残っている改善をすべて自律的に実装しきる**。
開発タスクがゼロになったときの永続エンジンとして機能する。

---

## バックログファイル

`docs/improve-backlog.md` に未実装の改善アイデアを保存・管理する。
このファイルが実装の唯一のソースオブトゥルースとなる。

---

## 実行フロー

```
0. LOAD     — バックログ確認（docs/improve-backlog.md が存在するか）
              存在する → STEP 5 へジャンプ（新規アイデア生成不要）
              存在しない → STEP 1 から実行
1. SCAN     — プロジェクト現状の全体把握
2. ANALYZE  — 改善領域の特定と分析
3. IDEATE   — 改善アイデアの生成（最低10件）
4. PRIORITIZE — 優先度付けしてバックログに保存
5. IMPLEMENT  — バックログの先頭から順に全件実装
6. REPORT   — 実施結果の報告
```

---

## STEP 0: LOAD（バックログ確認）

`docs/improve-backlog.md` を読む。

- **ファイルが存在して未実装アイデアが残っている** → STEP 5 へジャンプ
- **ファイルが存在しないまたは空** → STEP 1 から実行

---

## STEP 1: SCAN（現状把握）

以下をすべて確認する：

### コード・構成
- `src/app/` — ページ構成とルーティング
- `src/components/` — 既存コンポーネント一覧
- `docs/PRD.md` — PRDと完成定義
- `docs/specs/` — 機能仕様書
- `docs/journal/` — 開発ジャーナル（存在すれば）

### コンテンツ
- `content/lessons/` — レッスンファイルの数・構成

### 品質
```bash
npm run lint
npx tsc --noEmit
```

---

## STEP 2: ANALYZE（改善領域の特定）

以下の8領域を必ず評価する：

| 領域 | 評価観点 |
|------|---------|
| **UX/UI** | ナビゲーション・視認性・レスポンシブ対応・ダークモード |
| **パフォーマンス** | 画像最適化・コード分割・キャッシュ戦略 |
| **アクセシビリティ** | aria属性・キーボード操作・コントラスト比 |
| **コンテンツ品質** | レッスンの深さ・ハンズオンの充実度・クイズの質 |
| **学習体験** | 進捗可視化・達成感・学習パス |
| **新機能** | PRDに未記載だが価値の高い機能 |
| **コード品質** | 重複排除・型安全性・テスタビリティ |
| **SEO・メタデータ** | OGタグ・structured data・サイトマップ |

---

## STEP 3: IDEATE（アイデア生成）

各領域から改善アイデアを具体的に生成する（最低10件）。

アイデアの記述形式：
```
## アイデア: <タイトル>
- **領域**: <UX/UI | パフォーマンス | アクセシビリティ | コンテンツ品質 | 学習体験 | 新機能 | コード品質 | SEO>
- **説明**: <何を・なぜ・どう改善するか>
- **Impact**: High / Medium / Low（ユーザー価値）
- **Effort**: High / Medium / Low（実装コスト）
- **実装概要**: <具体的な変更内容>
```

---

## STEP 4: PRIORITIZE（優先度付けとバックログ保存）

Impact × Effort マトリクスで並び替える：

```
              Low Effort    Medium Effort   High Effort
High Impact   [最優先]      [優先]          [要検討]
Med Impact    [次点]        [余裕あれば]    [保留]
Low Impact    [いつか]      [スキップ]      [スキップ]
```

**スキップ対象（実装しない）：**
- Low Impact × Medium/High Effort
- 破壊的変更が必要なもの
- バックエンドが必要なもの（`develop` スキルに委譲）
- PRDに反するもの

**バックログへの保存：**

`docs/improve-backlog.md` を以下の形式で作成する：

```markdown
# 改善バックログ

<!-- 上から順に実装する。完了したアイテムは削除する。 -->

## 未実装

- [ ] **<タイトル>** | <領域> | Impact:<High/Med> | Effort:<Low/Med> | <実装概要1行>
- [ ] **<タイトル>** | <領域> | Impact:<High/Med> | Effort:<Low/Med> | <実装概要1行>
...

## 実装済み（このセッション）

（実装したものをここに移動する）
```

---

## STEP 5: IMPLEMENT（バックログを全件実装）

`docs/improve-backlog.md` の `## 未実装` セクションにあるアイテムを**上から順に全件実装する**。

各アイテムの実装手順：

### 5-1. バックログのアイテムを取得
未実装リストの先頭アイテムを選ぶ。

### 5-2. 設計確認
- 既存コードへの影響範囲を確認
- 変更するファイルを特定
- 破壊的変更がないか確認
  → 破壊的変更が必要な場合はスキップして次のアイテムへ

### 5-3. 実装
- 型定義 → コンポーネント → ページの順
- Server Components をデフォルト、`"use client"` は最小限
- `any` 型は使わない

### 5-4. 検証
```bash
npm run lint
npx tsc --noEmit
```
エラーがあれば修正してから次へ。

### 5-5. コミット
```
improve(<scope>): <改善内容の要約>
```

### 5-6. バックログ更新
実装完了したアイテムを `## 未実装` から `## 実装済み` セクションに移動する。
`docs/improve-backlog.md` を保存してコミットする：
```
chore(improve): バックログを更新
```

### 5-7. 繰り返し
`## 未実装` が空になるまで 5-1 〜 5-6 を繰り返す。

---

## STEP 6: REPORT（報告）

```markdown
## 改善実施レポート

### このセッションで実装した改善
1. **<タイトル>** — <変更内容の簡潔な説明>
2. **<タイトル>** — <変更内容の簡潔な説明>
...

### バックログの状態
- 実装済み合計: N件
- 残り: 0件（または N件）

次回 launch 時に新たなアイデアを生成して自動実装します。
```

---

## 判断基準（迷ったとき）

| 状況 | 判断 |
|------|------|
| 破壊的変更が必要なアイデア | スキップして次のアイデアへ |
| 外部ライブラリが必要 | `npm install` して進める |
| バックエンドが必要なアイデア | スキップ（`develop` スキルに委譲） |
| PRDに反するアイデア | スキップ |
| コンテンツ改善のアイデア | スキップ（`content` スキルに委譲） |
| 1件の実装に詰まった | スキップして次のアイデアへ（止まらない） |
