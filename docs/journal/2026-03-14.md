### 2. CLAUDE.mdの設計

### 3. Hooksによる品質ゲートの構築

`.claude/settings.json` にPostToolUseフックを設定：
- ファイル編集後に自動で `npm run lint` を実行
- 続けて `npx tsc --noEmit` で型チェック
- エラーをClaudeが即座に検知して自己修正できる環境を整備

### 4. スキルアーキテクチャの設計と構築

Claude Codeのスキル・コマンド・フックの違いを理解しながら、以下を設計：

| スキル | 役割 |
|---|---|
| `commit` | Conventional Commits形式で日本語コミット（~/.claude/skills/） |
| `design` | 機能の設計・仕様書作成 |
| `page` | Next.jsページ作成 |
| `component` | Reactコンポーネント作成 |
| `develop` | 1機能を設計〜コミットまで完結させるオーケストレーター |
| `ship` | PRD全タスクを自律実行する上位オーケストレーター |
| `content` | 教材コンテンツ（121レッスン）を並列作成 |
| `chronicle` | 開発プロセスを記録（このファイルを書くスキル） |
| `launch` | ship・content・chronicleを3並列で起動する最上位オーケストレーター |

### 5. PRD（製品要件定義書）の作成

対話形式でPRDを作成。主な決定事項：

- **ターゲット**: 生成AIを学びたいエンジニア
- **カリキュラム**: 全10チャプター・121レッスン
- **コンテンツ形式**: 記事 → ハンズオン → クイズ
- **進捗管理**: まずLocalStorage、後でログイン対応
- **コンテンツ管理**: Markdownファイル

## 意思決定メモ

### なぜスキルをプロジェクト内（`.claude/skills/`）に置いたか
このプロジェクト固有の規約（Next.js・Tailwind・ディレクトリ構成）を含むため、グローバル（`~/.claude/skills/`）ではなくプロジェクト内に配置。`commit` スキルだけは全プロジェクト共通で使えるのでグローバルに置いた。

### なぜ `launch` スキルを作ったか
「eラーニングツールを完成させて」という一言でアプリ実装・教材作成・開発記録の3トラックが並列で走るようにしたかった。`ship` だけだとコンテンツ作成と記録が直列になってしまうため、上位オーケストレーターとして `launch` を追加。

### CLAUDE.mdのスリム化
最初に詳細なCLAUDE.mdを作ったが、ユーザーから「コンテキスト消費が増える」という指摘を受けてスリム化。コンポーネント設計方針・命名規則・禁止事項はそれぞれのスキルに移した。これはハーネスエンジニアリングの重要な学びだった。

---

## ハーネスエンジニアリングの学び

1. **CLAUDE.mdは最小限に**: 常時読み込まれるため、詳細はスキルに分離する
2. **スキルはProgressive Disclosure**: メタデータ（常時）→ SKILL.md（発動時）→ 参照ファイル（必要時）の3層
3. **Hooksは品質の守り神**: AIが間違えたとき自分で気づいて直せる環境がないと長時間自律実行は機能しない
4. **並列実行は設計から**: 独立したトラックは最初から並列で設計するとスループットが上がる
5. **PRD駆動が自律開発のカギ**: 「何が完成した状態か」を定義しないとAIは途中で止まる
